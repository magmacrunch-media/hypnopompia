You need Xcode, and nothing else

No Apple developer account, no signing, no clone of anything, and no cable. These run on the simulator that comes with Xcode. The first app takes about an hour, nearly all of it downloading; every one after that takes a minute.

Apple renamed and rebuilt all of this in Xcode 27, released September 2026. The Simulator app was replaced by one called Device Hub, so older instructions, including the ones that used to be on this page, name menus that are not there. Step 2 is written both ways. Check which you have first: Xcode → About Xcode.

1. Install Xcode, and then install an iPhone to run

Xcode on its own cannot run anything. The iPhone is a second download, made from inside Xcode, and it is where most people get stuck: Xcode installs, you open it, and there is no iPhone to be found anywhere.

  1. Install Xcode from the Mac App Store. It is free and large, about 7 GB. If the App Store will not offer it, your macOS is too old for the current Xcode; see below.
  2. Open Xcode once and let it finish. It asks you to agree to a licence, then asks for your Mac login password so it can install its components. Both are expected.
  3. If a sheet appears offering components, tick iOS and click Install. If you have already clicked past it, go to Xcode → Settings, click Components in the sidebar, find iOS under Platform Support, and click Get.
  4. Let that download finish before going on. It is another 7 GB or so. Nothing below works until it has.

Allow roughly 20 GB of free disk for Xcode and one iOS version together. If the Components window is fighting you, this does the same job from the Terminal and is the same on every version:

xcodebuild -downloadPlatform iOS

2. Start an iPhone

Open Xcode → Open Developer Tool and look at what is in it. That menu tells you which of the two you have.

Xcode 27 and later: Device Hub.

  1. Choose Xcode → Open Developer Tool → Device Hub.
  2. Click the + button at the top of the sidebar and choose any iPhone from under Simulators. Pick the iOS version you downloaded, then click Create. It appears in the sidebar under Available.
  3. Select it in the sidebar and click Start in the middle of the window.

Xcode 26 and earlier: Simulator.

  1. Choose Xcode → Open Developer Tool → Simulator.
  2. If no iPhone appears, pick one from the Simulator's File → Open Simulator menu, or make one with File → New Simulator….

Either way, wait for the home screen. A first boot takes a couple of minutes and shows black, or an Apple logo, while it works. Nothing will install until you can see app icons.

3. Put an app on it

  1. Download an app below and double-click the zip. You get one file whose name ends .app. Safari may have unzipped it for you already, so look in Downloads before unzipping twice.
  2. Do not double-click the .app itself. It is an iPhone app, so your Mac refuses it, usually with “you can’t open the application because it is not supported on this Mac”. That message means the file is fine and is being opened in the wrong place.
  3. With the iPhone showing its home screen, open Terminal (Spotlight, type Terminal) and paste these two lines, one at a time. The bundle id is listed on the app below. 
    cd ~/Downloads
xcrun simctl install booted Whatever.app
    Then click the app on the home screen, or launch it from here: 
    xcrun simctl launch booted the.bundle.id
  4. If it is not on the first home-screen page, swipe left with two fingers on the trackpad, or swipe down from the middle of the screen and type the name.
Why the Terminal, and the drag-and-drop shortcut

Dragging the .app onto the iPhone's screen installs it too, and is quicker when it works. It was the normal way to do this with the old Simulator; Device Hub is new and the two lines above are what works everywhere, so they are what the steps say. Try the drag first if you prefer.

Device Hub's own Apps list will not take these. The + button under that list accepts only a finished .ipa, which is a signed App Store build. These are unsigned simulator builds, so that button is the wrong door and will simply refuse the file.

Useful when something is unclear:

xcrun simctl list devices available   # what exists, and what says (Booted)
xcrun simctl boot "<a name from that list>"

If those answer xcrun: error: unable to find utility "simctl", the Mac is pointed at the Command Line Tools rather than at Xcode. Point it at Xcode and try again:

sudo xcode-select -s /Applications/Xcode.app/Contents/Developer

If something goes wrong

  • There is no Simulator in the Open Developer Tool menu. You are on Xcode 27 or later, which replaced it with Device Hub. Same thing, new name and new window; follow the Xcode 27 half of step 2.
  • There is no iPhone to start, in either of them. Xcode has no iOS platform yet. Go back to step 1 and get iOS from Xcode → Settings → Components, or run xcodebuild -downloadPlatform iOS. This is the usual answer when the simulator seems to be missing.
  • Device Hub says a simulator is “incompatible”. It was made by an older Xcode against an iOS version this one does not have. Get that iOS version in Components, or make a new simulator on a version you do have. xcrun simctl list runtimes says what is really installed.
  • The + button in Device Hub's Apps list refuses the file. That button takes only a signed .ipa. These are unsigned simulator builds; install them with the xcrun simctl install booted line in step 3.
  • Neither app is anywhere to be found. Both arrive inside Xcode rather than on their own, and only after Xcode has been opened once. Installing the Command Line Tools is not the same thing and brings no simulator with it.
  • Nothing happens when you drag it on. The iPhone has to be started first, showing a home screen rather than a black rectangle, and the drop has to land on the screen rather than on the surround. Dragging is a shortcut; the xcrun simctl install booted line in step 3 is the one that always works.
  • It installed, and then you cannot find it. It is on the home screen like any other app, possibly on the second page. Swipe left with two fingers, or swipe down from the middle of the screen and type the name.
  • “App.app is damaged”. macOS quarantines anything downloaded. Run xattr -dr com.apple.quarantine App.app and try again.
  • “Not supported on this Mac” when you open the .app. That is an iPhone app and you are opening it on the Mac. Drag it onto the simulator instead; nothing is wrong with it.
  • “Unsupported architecture”. Check the architectures listed on the app against your Mac. arm64 is an Apple Silicon Mac (M1 and later), x86_64 an Intel one. The Apple menu → About This Mac says which you have.
  • The simulator is too old. Each app lists the minimum iOS it needs. Xcode → Settings → Components installs other versions.
  • The iPhone sits on black, or refuses to start. Quit the window and open it again, then start the device a second time. If it still will not come up, erase it and start it once more: xcrun simctl erase <the device name>.
  • The App Store will not install Xcode. Your macOS is older than the current Xcode needs. Older versions are at developer.apple.com/download/all, which wants a free Apple ID to sign in and no paid membership. Search for Xcode, take the newest one your macOS will accept, and drag it into Applications.

What a simulator cannot show you

  • Game Center. These are built unsigned and without entitlements, so leaderboards and achievements do nothing. That needs a paid Apple Developer membership, which does not exist yet.
  • Haptics. There is no taptic engine in a simulator, so anything that should buzz is silent.
  • Real speed, and a real touchscreen. A trackpad pretending to be a finger on a Mac pretending to be a phone. Layout, wording and rules are worth reporting from here; how something feels is not.
